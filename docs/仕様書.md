## 1. 概要

VBA Formatter は、Excel / Access などの Visual Basic Editor（VBE）に組み込んで使う、VBA コードのインデント整形アドインです。

### 1.1 目的

- 有償化された SmartIndenter の代わりとして、同程度のインデント整形を無償で使えるようにする。
- Rubberduck のように起動に時間がかかる高機能ツールではなく、整形だけに絞った軽量ツールにする。

### 1.2 要件と対応

| 要件 | 対応 |
|---|---|
| プログラムのコードを整形できる | ブロック構造に合わせてインデントを付け直す（[5. 整形仕様](#5-整形仕様)） |
| 簡単にインストールできる | `install.bat` を実行するだけ。管理者権限は不要 |
| VBE から直接操作して整形できる | VBE のメニューバー、右クリックメニュー、ショートカットキーから実行 |

### 1.3 対象外

次の機能は持ちません。

- 空白の入れ方やキーワードの大文字・小文字の統一（VBE が自動で直すため）
- 空行の削除・圧縮など、行数が変わる整形
- 静的解析、リファクタリング、単体テストなど Rubberduck にある機能

## 2. 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11 |
| .NET | .NET Framework 4.8（Windows 10 / 11 には標準で入っている） |
| Office | VBA 7 を搭載した Office（Office 2010 以降・Microsoft 365）。32bit 版・64bit 版の両方に対応 |
| ホスト | Excel、Access、Word など、VBE を持つ Office アプリ |
| 権限 | 一般ユーザー権限で可（管理者権限は不要） |

- Office のセキュリティ設定「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」は不要です。VBE アドインは VBE から直接オブジェクトを受け取るため、この設定の影響を受けません。
- 動作確認済みの環境は Microsoft 365（64bit）の Excel です。Access でも VBE の仕組みは共通なので動作する想定ですが、実機ではまだ確認していません。

## 3. インストール・アンインストール

### 3.1 配布物

`VbaFormatter-<バージョン>.zip` を展開すると、次のファイルが入っています。

| ファイル | 役割 |
|---|---|
| `VbaFormatter.dll` | アドイン本体 |
| `install.bat` / `install.ps1` | インストーラー |
| `uninstall.bat` / `uninstall.ps1` | アンインストーラー |
| `README.md` | 簡易説明 |

### 3.2 インストール手順

1. Excel / Access / Word / PowerPoint / Outlook をすべて終了します。
2. zip を任意のフォルダーに展開します。
3. `install.bat` をダブルクリックします。
4. 「インストールが完了しました」と表示されたら、任意のキーを押して画面を閉じます。
5. Excel や Access を起動し、`Alt+F11` で VBE を開きます。
6. メニューバーの「アドイン」と「ウィンドウ」の間に **整形(J)** が追加されていれば完了です。

Office を起動したままインストールすると、警告が表示されます。初回のインストールならそのまま完了し、Office を再起動すれば使えるようになります。更新インストールで DLL が使用中の場合は、コピーに失敗してエラーになるので、Office を終了してからもう一度実行してください。

### 3.3 更新

新しいバージョンの zip を展開して `install.bat` を実行します。古い DLL と登録情報は上書きされます。設定ファイルはそのまま引き継がれます。

### 3.4 アンインストール

1. Office をすべて終了します。
2. `uninstall.bat` をダブルクリックします。

レジストリの登録と DLL を削除します。設定ファイル（`%APPDATA%\VbaFormatter\settings.ini`）は残すので、不要なら手動で削除してください。

### 3.5 インストーラーが行う処理

ユーザー単位（HKCU）の登録だけを行い、システム全体には影響しません。

**ファイルの配置**

| パス | 内容 |
|---|---|
| `%LOCALAPPDATA%\VbaFormatter\VbaFormatter.dll` | アドイン本体。コピー後に「インターネットから取得したファイル」の印（Zone.Identifier）を解除する |

**レジストリの登録**

| キー | 内容 |
|---|---|
| `HKCU\Software\Classes\CLSID\{607D618A-9D3E-4359-8B98-D12F7CDD63BA}` | COM クラスの登録（64bit 用） |
| `HKCU\Software\Classes\WOW6432Node\CLSID\{607D618A-9D3E-4359-8B98-D12F7CDD63BA}` | COM クラスの登録（32bit 用） |
| `HKCU\Software\Classes\VbaFormatter.Connect` | ProgID |
| `HKCU\Software\Microsoft\VBA\VBE\6.0\Addins\VbaFormatter.Connect` | VBE アドインの登録（32bit Office 用） |
| `HKCU\Software\Microsoft\VBA\VBE\6.0\Addins64\VbaFormatter.Connect` | VBE アドインの登録（64bit Office 用） |

- COM クラスの `InprocServer32` には `mscoree.dll`、クラス名 `VbaFormatter.AddIn.Connect`、アセンブリ名、ランタイム `v4.0.30319`、`CodeBase` を登録します。
- `CodeBase` は `file:///C:/Users/…/VbaFormatter.dll` の形式で、パーセントエンコードせずに書き込みます。エンコードすると、ユーザー名などに日本語を含むパスで DLL を読み込めなくなるためです。
- VBE アドインのキーには `FriendlyName`、`Description`、`LoadBehavior = 3`（起動時に読み込む）、`CommandLineSafe = 0` を設定します。

## 4. 使い方

### 4.1 コマンド一覧

| コマンド | メニュー | 右クリックメニュー | 既定のショートカット |
|---|---|---|---|
| プロシージャ/選択範囲を整形 | 整形 → プロシージャ/選択範囲を整形(P) | ○ | `Ctrl+Shift+F` |
| モジュールを整形 | 整形 → モジュールを整形(M) | ○ | なし |
| プロジェクト全体を整形 | 整形 → プロジェクト全体を整形(A) | | なし |
| 直前の整形を元に戻す | 整形 → 直前の整形を元に戻す(U) | | なし |
| 設定 | 整形 → 設定(S)... | | なし |

メニューはキーボードからも開けます（`Alt+J` → 各項目のアクセスキー）。

### 4.2 整形の範囲

**プロシージャ/選択範囲を整形**

| 状況 | 整形する範囲 |
|---|---|
| 複数行を選択している | 選択した行。選択の終わりが行頭（1 桁目）の場合、その行は含めない |
| 選択していない（1 行内の選択を含む） | カーソル位置のプロシージャ。直前のコメント・空行を含む、VBE が認識する範囲全体 |
| カーソルが宣言セクションにある | 宣言セクション全体 |

**モジュールを整形**

表示中のコード ウィンドウのモジュール全体を整形します。

**プロジェクト全体を整形**

アクティブな VBA プロジェクトに含まれる、すべてのモジュールを整形します（標準モジュール、クラス、フォーム、シート、ThisWorkbook など）。

- 終わると、整形したモジュール数と変更した行数をメッセージで表示します。
- 整形できなかったモジュールがあれば、その名前も表示します。

### 4.3 整形の共通動作

- インデントの深さは、範囲指定の有無に関係なく、常にモジュール全体を解析して決めます。そのため、一部だけを整形しても前後との整合が保たれます。
- 内容が変わる行だけを書き換えます。変更がない行には触りません。
- 整形の前後で、カーソル位置・選択範囲・表示位置（先頭行）を維持します。カーソル列はインデントの増減に合わせて補正します。
- ロックされたプロジェクトは整形できません。メッセージで通知します。
- コード ウィンドウが開いていないときは、「コード ウィンドウを開いてから実行してください」と表示します。

### 4.4 ショートカットキーの動作

- VBE のウィンドウ（または VBE が所有するウィンドウ）が最前面のときだけ反応します。Excel のワークシートなどを操作しているときは反応しません。
- ショートカットとして使ったキー入力は、VBE には渡しません。
- 押しっぱなしによるキーリピートは無視します。

## 5. 整形仕様

### 5.1 基本方針

- 変えるのは各行の**先頭の空白（インデント）**と**行末の空白**だけです。行の中身は変えません。
- 入力と出力の**行数は常に同じ**です。ブレークポイントやブックマークの位置はずれません。
- 空白だけの行は空行にします。
- 文字列リテラル（`"…"`、`""` によるエスケープを含む）とコメント（`'` 以降、`Rem` 文）の中は、構文の判定に使いません。

### 5.2 インデントを付けるブロック

| 開始 | 中間 | 終了 | 備考 |
|---|---|---|---|
| `Sub` / `Function` / `Property Get/Let/Set` | | `End Sub` / `End Function` / `End Property` | `Public` `Private` `Friend` `Global` `Static` の修飾子に対応。`Declare` 文は対象外 |
| `If … Then`（ブロック形式） | `ElseIf` / `Else` | `End If` / `EndIf` | 中間の行は開始と同じ位置 |
| `Select Case` | `Case` / `Case Else` | `End Select` | `Case` の行は `Select Case` より 1 段深く、その中身はさらに 1 段深い（設定で変更可） |
| `For` / `For Each` | | `Next` | `Next i, j` は変数の数だけブロックを閉じる |
| `Do`（`Do While` / `Do Until` を含む） | | `Loop`（`Loop While` / `Loop Until` を含む） | |
| `While` | | `Wend` | |
| `With` | | `End With` | |
| `Type` | | `End Type` | 設定でメンバーのインデントを無効にできる |
| `Enum` | | `End Enum` | 同上 |
| `#If` | `#ElseIf` / `#Else` | `#End If` | 詳しくは [5.6](#56-コンパイラ指令if) |

インデント 1 段の幅は、既定でスペース 4 個です。

### 5.3 1 行 If

`Then` の後ろに、コメント以外の文が同じ論理行にある場合は 1 行 If とみなし、ブロックとして扱いません。

```vba
If x Then y = 1                ' 1 行 If
If x Then y = 1 Else y = 2     ' 1 行 If
If x Then: y = 1               ' 1 行 If
If x Then ' コメント            ' ブロック If（コメントは無視）
If a = 1 And _
    b = 2 Then                 ' ブロック If（継続行を連結して判定）
```

1 行 If の中に `Loop` や `End If` などがあっても、ブロックの開始・終了とはみなしません。

### 5.4 1 行に複数の文がある場合（`:` 区切り）

- `:` で区切られた文を先頭から順に解析し、ブロックの開閉を反映します。
- その行の位置は、先頭の文で決まります。
- 名前付き引数の `:=` は区切りとみなしません。

```vba
Do: x = x + 1: Loop Until x > 5    ' Do と Loop が同じ行にあるので、インデントは増えない
Case 2, 3: F = "two or three"      ' Case 行として扱う
```

### 5.5 行ラベルと行番号

- 行頭の行ラベル（`ErrHandler:` など）と行番号（`10`、`100` など）は、常に 1 桁目に置きます。
- ラベルの後ろに文がある場合は、その文を本来のインデント位置に置きます。ラベルがインデント位置より長いときは、ラベルの後ろに空白を 1 つ入れて続けます。
- 次の語に `:` が続く場合はラベルとみなしません。`Else` `End` `Exit` `Loop` `Next` `Wend` `Do` `Resume` `Return` `Stop` `Rem` `Call` `GoSub` `GoTo` `With` `Select` `Case` `If` `ElseIf` `For` `While`
- ラベル名には日本語（Unicode 文字）を使えます。

```vba
Sub A()
    On Error GoTo エラー処理
10  x = 1
100 y = 2
    Exit Sub
エラー処理:
    MsgBox Err.Description
End Sub
```

### 5.6 コンパイラ指令（#If）

**既定の動作（設定「#If ～ #End If の中をインデントする」がオン）**

- `#If` / `#ElseIf` / `#Else` / `#End If` の行は、その時点のインデント位置に置き、中身を 1 段深くします。

**設定をオフにした場合**

- 指令の行は常に 1 桁目に置き、中身のインデントには影響させません。

**各分岐の扱い**

- `#Else` / `#ElseIf` の分岐は、`#If` の直後と同じ状態から解析を始めます。
- `#End If` の後は、最初の分岐が終わった時点の状態を引き継ぎます。
- これにより、次のようにプロシージャ宣言を `#If` で切り替えるコードも正しく整形できます。

```vba
#If VBA7 Then
    Private Function H() As LongPtr
#Else
    Private Function H() As Long
#End If
    H = 0
End Function
```

### 5.7 行継続（` _`）

- 行末が「空白＋`_`」の行は、次の行と合わせて 1 つの論理行として扱います。コメントの行末に `_` がある場合も、VBA の仕様どおり継続とみなします。
- 1 行目は通常どおりインデントします。
- 2 行目以降の位置は次のとおりです（設定「継続行の相対位置を保持する」がオンの場合）。

| 元の位置 | 整形後の位置 |
|---|---|
| 1 行目より右にある | 1 行目からの相対位置（ずれ幅）を保ったまま、1 行目と一緒に移動する。括弧の位置にそろえたものなどが崩れない |
| 1 行目と同じかそれより左にある | 1 行目の位置＋「継続行の追加インデント」段（既定 1 段） |

- 設定をオフにすると、2 行目以降はすべて「1 行目の位置＋追加インデント段数」にそろえます。

```vba
' 整形前                         ' 整形後
        Call Foo(a, _               Call Foo(a, _
                 b)                          b)
s = "a" & _                         s = "a" & _
"b"                                     "b"
```

### 5.8 コメント行

- コメントだけの行は、既定ではその位置のコードと同じインデントにします。
- 設定「コメント行もインデントする」をオフにすると、元の位置のまま変えません（行末の空白だけ削除します）。
- `End If` や `Else` の直前にあるコメント行は、ブロックの内側の位置になります。

### 5.9 タブ

- 設定「インデントにタブを使う」がオンの場合、インデントをタブで表現します。端数が出るときはスペースで補います。
- 元のコードに含まれるタブは、インデント幅ごとのタブ位置として桁数を計算します。

### 5.10 構造が崩れたコードへの対応

- `End If` が足りないなど、ブロックの対応が取れていないコードでもエラーにはしません。
- 対応する開始がない終了文は無視します。
- プロシージャの開始・終了（`Sub` / `End Sub` など）の位置で、`#If` 以外の開いたままのブロックをすべて閉じます。そのため、崩れの影響は次のプロシージャまで及びません。

### 5.11 整形例

```vba
Option Explicit

Public Sub Test(ByVal n As Long)
    Dim i As Long
    On Error GoTo ErrHandler
    For i = 1 To n
        If i Mod 2 = 0 Then
            Debug.Print "even: If x Then"
        Else
            Select Case i
                Case 1
                    Debug.Print "one"
                Case Else
                    Debug.Print "other"
            End Select
        End If
    Next i
    MsgBox "a" & _
        "b"
    Exit Sub
ErrHandler:
    MsgBox Err.Description
End Sub
```

## 6. 設定

### 6.1 設定画面

「整形 → 設定」で開きます。

- 右側のプレビューで、サンプルコードの整形結果を確認しながら変更できます。
- 「既定値に戻す」で整形オプションを既定値に戻せます（ショートカットキーは戻りません）。
- 「OK」を押すと保存され、次の整形からすぐに反映されます。

### 6.2 設定項目

| 画面の表示 | キー（settings.ini） | 既定値 | 範囲・説明 |
|---|---|---|---|
| インデント幅 | `IndentSize` | `4` | 1〜16 |
| インデントにタブを使う | `UseTabs` | `False` | |
| プロシージャの本体をインデントする | `IndentProcedureBody` | `True` | |
| Select Case 内の Case をインデントする | `IndentCase` | `True` | オフにすると `Case` を `Select Case` と同じ位置に置く |
| Type / Enum のメンバーをインデントする | `IndentTypeAndEnumMembers` | `True` | |
| #If ～ #End If の中をインデントする | `IndentCompilerDirectives` | `True` | オフにすると指令は 1 桁目 |
| コメント行もインデントする | `IndentCommentLines` | `True` | |
| 継続行（ _）の相対位置を保持する | `PreserveContinuationAlignment` | `True` | |
| 継続行の追加インデント（段） | `ContinuationIndentLevels` | `1` | 0〜8 |
| ショートカット: プロシージャ/選択範囲 | `FormatCurrentHotkey` | `Ctrl+Shift+F` | 空欄で無効 |
| ショートカット: モジュール | `FormatModuleHotkey` | （空欄） | 空欄で無効 |

### 6.3 ショートカットキーの書き方

- `Ctrl` `Shift` `Alt` とキー名を `+` でつなげて書きます。例: `Ctrl+Shift+F`、`Ctrl+Alt+I`、`F12`
- キー名には英字、数字、`F1`〜`F24`、そのほか .NET の `Keys` 列挙体の名前（例: `Home`、`OemPeriod`）を使えます。
- 誤って通常の文字入力を奪わないよう、`Ctrl` も `Alt` も含まない組み合わせはファンクションキー（`F12`、`Shift+F5` など）に限ります。`Shift+F` のような組み合わせは登録できません。
- 解釈できない値は、設定画面の OK 時にエラーにします。

### 6.4 設定ファイル

- 保存先は `%APPDATA%\VbaFormatter\settings.ini`（UTF-8）です。
- 画面を使わずに直接編集することもできます。その場合、変更は次に Office を起動したときに読み込まれます。
- 値は `True` / `False`（`1` / `0` も可）または整数で書きます。範囲外の値は上限・下限に丸めます。

```ini
[Format]
IndentSize=4
UseTabs=False
IndentProcedureBody=True
IndentCase=True
IndentTypeAndEnumMembers=True
IndentCompilerDirectives=True
IndentCommentLines=True
PreserveContinuationAlignment=True
ContinuationIndentLevels=1
[Hotkeys]
FormatCurrentHotkey=Ctrl+Shift+F
FormatModuleHotkey=
```

## 7. 元に戻す機能

- VBE の「元に戻す」（`Ctrl+Z`）では、アドインによる変更を戻せません。「整形 → 直前の整形を元に戻す」を使ってください。
- 戻せるのは**直前の 1 回分**の整形だけです。プロジェクト全体の整形なら、全モジュール分をまとめて戻します。
- 整形した後に手で編集した行など、整形直後の内容から変わっている行は戻しません（上書きによる消失を防ぐため）。戻せなかった行がある場合は、その行数をメッセージで表示します。
- 戻す情報はメモリ上にだけ保持します。Office を終了すると消えます。

## 8. 制限事項・既知の注意点

| 項目 | 内容 |
|---|---|
| Access での動作 | 仕組み上は動作する想定だが、実機ではまだ確認していない |
| `Else If`（空白あり）と書いた行 | `Else` の後ろにブロック If を同じ行に書く形式には対応していない |
| メニューに表示されるショートカット | メニューの右側に表示されるショートカットの文字は、起動時の設定で決まる。設定を変えてもキーの割り当て自体はすぐ反映されるが、表示は Office を再起動するまで古いまま |
| 他アドインとのキーの重複 | Rubberduck など、ほかのアドインとショートカットキーが重なる場合は設定で変更する |
| 中断モード中の整形 | デバッグの中断中に整形すると、VBE が「プロジェクトをリセットする」旨の確認を出す場合がある |
| エクスポートしたファイル（.bas / .cls） | VBE 上での整形専用。ファイルを直接整形するコマンドラインツールは未提供 |

## 9. トラブルシューティング

| 症状 | 確認すること |
|---|---|
| メニューに「整形」が出ない | ① `install.bat` を Office 終了後に実行したか ② VBE の「アドイン → アドイン マネージャー」で「VBA Formatter」が「ロード」になっているか ③ ログ（下記）にエラーが出ていないか |
| アドイン マネージャーに表示されない | Office のビット数に対応するレジストリキー（`Addins` / `Addins64`）が登録されているか。`install.bat` を再実行する |
| ショートカットキーが効かない | ① VBE のウィンドウが最前面か ② 設定画面でキーが正しく登録されているか ③ ほかのアドインやツールが同じキーを使っていないか |
| 整形結果がおかしい | どのような書き方で崩れるか、該当コードの例を開発者に伝える |
| 更新インストールで DLL をコピーできない | Office（Outlook を含む）をすべて終了してから再実行する |

ログは `%LOCALAPPDATA%\VbaFormatter\VbaFormatter.log` に出力されます。アドインの読み込み、初期化、エラーを記録します。512KB を超えると削除し、新しく作り直します。

## 10. 内部構成（開発者向け）

### 10.1 ディレクトリ構成

```
vba-formatter/
├─ src/
│  ├─ VbaFormatter.Core/      整形エンジン（Office 非依存、netstandard2.0）
│  │   ├─ FormatterOptions.cs   整形オプション
│  │   └─ VbaIndenter.cs        インデント整形の本体
│  └─ VbaFormatter.AddIn/     VBE 用 COM アドイン（net48、出力は VbaFormatter.dll）
│      ├─ Connect.cs            COM のエントリポイント（IDTExtensibility2 の実装）
│      ├─ Extensibility.cs      IDTExtensibility2 などの COM 定義
│      ├─ MenuManager.cs        メニューバー・右クリックメニューの追加と削除
│      ├─ KeyboardHook.cs       ショートカットキー（スレッド単位のキーボードフック）
│      ├─ FormatService.cs      整形コマンド、範囲の決定、カーソル位置の復元、元に戻す
│      ├─ Settings.cs           設定の読み書き、ショートカットキーの解析
│      ├─ SettingsForm.cs       設定画面（WinForms、プレビュー付き）
│      ├─ Log.cs                ログ出力
│      └─ lib/                  ビルド用の相互運用アセンブリ（Microsoft.Vbe.Interop、office）
├─ tests/VbaFormatter.Tests/  整形エンジンの単体テスト（xUnit、net10.0）
├─ installer/                 install / uninstall のスクリプト
├─ docs/                      ドキュメント
└─ build.ps1                  テスト・ビルド・パッケージ作成
```

### 10.2 設計上の要点

**1 つの DLL にまとめる**
- 整形エンジンのソースはアドインのプロジェクトに取り込んで、1 つの DLL にしています。
- Office から COM 経由で読み込まれた DLL は、依存する DLL を Office 側のフォルダーから探します。DLL を分けると、その解決が失敗しやすいためです。

**相互運用型の埋め込み**
- `Microsoft.Vbe.Interop` と `office` は、相互運用型を DLL に埋め込んでいます（EmbedInteropTypes）。
- 利用者の環境に Office の PIA がなくても動作します。

**IDTExtensibility2 の自前定義**
- Extensibility.dll を参照せず、IDTExtensibility2 を自前で定義しています。

**32bit / 64bit 両対応**
- DLL は AnyCPU でビルドし、レジストリの 32bit 用・64bit 用の両方に登録しています。

**初期化のタイミング**
- 起動時に読み込まれた場合（`ext_cm_Startup`）は、メニューの準備が整う `OnStartupComplete` で初期化します。
- それ以外の場合は `OnConnection` ですぐに初期化します。

**GC 対策**
- VBE が COM 参照を保持し続ける保証がないため、`Connect` のインスタンスを static 変数で保持しています。保持しないと、時間が経ってからショートカットが効かなくなることを確認しています。

**メニューのイベント**
- `VBE.Events.CommandBarEvents` を使っています。
- イベント オブジェクトへの参照を保持しないとクリックが届かなくなるため、リストで保持しています。
- 異常終了時に残ったメニューは、次回起動時にタグで探して削除します。

**ショートカットキー**
- `SetWindowsHookEx(WH_KEYBOARD)` で、Office の UI スレッドにだけキーボードフックを掛けています。
- 整形処理はフックの中では実行せず、メッセージ専用ウィンドウ（`HWND_MESSAGE`）に `PostMessage` して、メッセージループに戻ってから実行します。
- 当初使っていた WinForms の `Control.BeginInvoke` は、Office の中では処理が届かないことがあったため採用していません。

**行数を変えない**
- 整形エンジンは常に入力と同じ行数を返します。
- そのため、アドイン側は変わった行だけを `CodeModule.ReplaceLine` で書き換えるだけで済み、範囲指定やカーソル位置の補正も単純になっています。

### 10.3 整形エンジンの処理の流れ

1. 行に分割し、行継続でつながった物理行を 1 つの論理行にまとめる。
2. 論理行ごとに、文字列リテラルの中身を伏せ、コメントを取り除いたコード部分を作る。
3. 行頭のラベル・行番号を取り出す。
4. コード部分を `:` で文に分け、各文をブロックの開始・中間・終了に分類する。
5. ブロックのスタックを更新し、その行のインデント段数を決める。
6. `#If` の分岐では、スタックの状態を保存・復元する（[5.6](#56-コンパイラ指令if)）。
7. 1 行目のインデントを付け、継続行の位置を計算して出力する。

## 11. ビルド・テスト・配布（開発者向け）

### 11.1 必要なもの

- .NET SDK 10 以降（テストプロジェクトが net10.0 を対象にしているため。アドイン本体の .NET Framework 4.8 向けビルドにも使う）
- テストの初回実行時に NuGet から xUnit などを取得するため、インターネット接続

### 11.2 コマンド

```powershell
# テストのみ
dotnet test tests\VbaFormatter.Tests

# テスト → Release ビルド → 配布用 zip の作成（dist\VbaFormatter-<バージョン>.zip）
.\build.ps1

# 開発中のビルドをこのマシンにインストール（Office は終了しておく）
.\installer\install.ps1 -Source src\VbaFormatter.AddIn\bin\Release\net48
```

### 11.3 バージョンの更新

1. `src/VbaFormatter.AddIn/VbaFormatter.AddIn.csproj` の `Version`、`AssemblyVersion`、`FileVersion` を変更する。
2. `build.ps1` を実行する。

インストーラーは、DLL からアセンブリ名とバージョンを読み取ってレジストリに登録します。そのため、インストーラー側の修正は不要です。

### 11.4 注意事項

- **CLSID を変えない**：`607D618A-9D3E-4359-8B98-D12F7CDD63BA` は、`Connect.cs` とインストーラー 2 本で一致させる必要があります。変更すると、既存の環境に古い登録が残ります。
- **.ps1 は BOM 付き UTF-8 で保存する**：Windows PowerShell 5.1 は、BOM のない UTF-8 の日本語を正しく読めません。
- **.bat には日本語を書かない**：文字コードの問題を避けるため、ASCII 文字だけにしています。
- **整形ルールを変えたらテストを追加する**：期待する整形結果を `tests/VbaFormatter.Tests/IndenterTests.cs` に追加します。テストは「インデントを全部取り除いた入力を整形すると期待値に戻ること」と「期待値を再度整形しても変わらないこと（冪等性）」の両方を確認する作りになっています。
